# Good КП. Дизайн системы

Дата: 10.09.2026. 

## 1. Что это

Good КП берет коммерческое предложение (КП) и несколько ответов на вопросы и выдает
один HTML-файл: интерактивный разбор КП по методике Вадима Школьного, прочитанный
глазами трех синтетических людей на стороне клиента (гендир, инициатор, технический
исполнитель). Эталон интерфейса: `tests/fixtures/prototype.html`
(прототип на КП «Пиксель Лаб» для «СтройМаркета»).

Инженерный принцип: весь интерфейс и вся интерактивность детерминированы и живут
в шаблоне. Модель возвращает только данные по строгой JSON-схеме. Модель никогда
не пишет HTML.

Два пути к одному и тому же файлу:

- Продажник без кода. Скачивает репозиторий, открывает `paste.html`, прогоняет `prompt.md`
  вместе с текстом КП в чат с моделью, вставляет полученный JSON в поле,
  видит отчет, жмет «Сохранить HTML». Хостинга нет, файл работает локально.
- Инженер. `uv run goodkp run kp.pdf --answers answers.yaml -o report.html`.
  Тот же шаблон, тот же JSON, тот же файл.

Доступ: репозиторий публичный, ссылка на него не публикуется в постах, ее выдает
телеграм-бот после проверки подписки на @vintersbrain и @ShkolnyiAccount. Гейт
мягкий, утечка ссылки допустима.

## 2. Решения, принятые на брейншторме

- Рендер живет в HTML (вариант A). Никакого Jinja2. Python вставляет JSON в шаблон
  и оборачивает каркасом. Один рендер для обоих путей.
- Только темная тема. Светлые токены удаляются, `<meta name="color-scheme" content="dark">`.
  Исключение: исправленная первая страница в «Почте» и ее docx/PDF остаются белыми,
  это документ.
- Меню (pillnav) подсвечивает текущий раздел: scrollspy через IntersectionObserver,
  активная пилюля со светлым фоном и темным текстом как выбранный сегмент в iOS,
  меню само прокручивается к активной пилюле на узком экране. При
  `prefers-reduced-motion` без анимации.
- Автор методики описывается в `rubric.yaml` одним объектом (имя, должность,
  канал, ссылки), в тексте шаблона не хардкодится. Текущая должность:
  «коммерческий директор в Серч, ex-коммерческий директор MAX».
- Язык: Python 3.11+, `uv`, PEP 723 не используется (это пакет, не скрипт).
- Бот: Python, serverless на Vercel, webhook.

## 3. Структура репозитория

```
good-kp/

  schema/report.schema.json      СГЕНЕРИРОВАН из pydantic-моделей
  template/report.html           эталон интерфейса без каркаса, с пустым <script id="data">
  paste.html                     страница вставки JSON, СОБИРАЕТСЯ из шаблона, открывается локально
  goodkp/

    intake.py                    чтение КП из pdf/docx/pptx/txt, вопросы intake
    rubric.py                    загрузка rubric.yaml, генерация prompt.md
    schema.py                    pydantic-модели отчета, экспорт JSON-схемы
    model.py                     вызов модели со структурированным выводом
    typo.py                      типографский проход и проверки голоса
    render.py                    вставка JSON в шаблон, каркас, сборка docs/index.html
  bot/
    api/webhook.py               Vercel-функция, проверка подписки
    vercel.json
  tests/
    golden/stroymarket/          kp.txt, answers.yaml, report.json

  scripts/build.py               rubric -> prompt.md, schema.json, docs/index.html
```

## 4. Поток данных

```
КП (pdf/docx/pptx/txt) + answers.yaml
  -> intake.py: текст КП с нумерацией абзацев (якоря src-N), ответы intake
  -> rubric.py: системный промпт = методика + персоны + правила голоса + схема
  -> model.py: модель, structured output, до 2 повторов при невалидном JSON
  -> schema.py: валидация pydantic, отказ если поле refusal заполнено
  -> typo.py: nbsp, е вместо ё, проверки на «—», «·», «не X, а Y», клише
  -> render.py: JSON в <script id="data">, каркас, standalone report.html
```

Путь без кода идет тем же маршрутом, только шаги model и typo делает человек:
`prompt.md` содержит те же правила голоса, а страница вставки прогоняет
типографский проход и проверки в JS перед рендером и показывает найденные
нарушения списком, не блокируя рендер.

## 5. Контракт данных (report.json)

Верхний уровень. Все строки на русском, без ё, без «—», без «·».

- `version`: версия схемы (semver строкой).
- `methodology_version`: из rubric.yaml, печатается в подвале.
- `refusal`: null или объект `{reason, hint}`. Если заполнено, остальные поля
  могут отсутствовать, отчет не рендерится, CLI печатает reason и выходит с кодом 2.
  Причины: не КП (нет предложения, цены или исполнителя), слишком короткий текст
  (меньше 600 символов), не на русском.
- `meta`: `kp_number`, `kp_date`, `vendor`, `client`, `run_date` (ISO, Europe/Moscow),
  `title` (заголовок h1, до 60 символов, утверждение без двоеточий).
- `intake`: массив `{k, v}` из шести пар: клиент, проект, кто получит КП, стадия,
  цель у клиента, бюджет. Значения из answers.yaml, модель их только сжимает.
- `readers`: массив ровно из трех персон в порядке ЛПР, ЛВР-инициатор, ЛВР-исполнитель.
  Персона: `name`, `role` (короткая подпись «гендир «СтройМаркета»»), `kind`
  (`decider|champion|executor`), `matters` (что важно), `reads` (как читает),
  `outcome` (итог одной фразой), `feed`: массив из 6 или 7 записей
  `{step, text, state, badge?}`, где `step` в списке `pre,1..6`, `state` в `ok|drop|off`,
  `badge` обязателен при `state: drop` и это короткая подпись в роде персоны («Закрыл файл», «Отвалилась», «Споткнулся»).
  `pre` только у decider (сначала цена).
- `chat`: массив сообщений hero-переписки, 8..14 штук:
  `{side: me|them, name?, text (пустой допустим только при file), file?: {name, size}, status?: Прочитано|Доставлено,
  timer?: start|stop}`. Тайминги набора и пауз шаблон считает сам по длине текста.
  Ровно одно `timer:start` и одно `timer:stop`.
- `verdict`: `{speaker, text}`. Голос гендира, 25..60 слов. Длительность записи
  шаблон считает по словам.
- `blocks`: массив ровно из шести опор в порядке рубрики:
  `{id: 1..6, title, summary (до 60 символов), state: ok|weak|crit, quote,
  quote_src (null или "src-N"), why, do, was, now}`.
  `state` определяет подпись в строке: `ok` «Прошло», `weak` «Споткнулся»,
  `crit` «Отвалился». `quote` цитата из КП или «Раздела нет. Ближайшее к теме: …».
- `flags`: массив из 4..6 уведомлений `{from, text}`, экран блокировки, отправитель
  всегда одна из трех персон.
- `holds`: массив из 2..5 записей `{title, text}`, что уже держит.
- `fixed_page`: `{subject, from_initials, contacts, sections: массив ровно из 6 {title, text}}`.
  `contacts` это строка подвала письма: исполнитель, контактное лицо, телефон, почта из исходного КП.
  Шапка письма: от `meta.vendor`, кому `readers[1].name`, дата и время из `meta.run_date`.
  Текст секций собирается из `blocks[].now`, но модель может переписать связно.
  Плейсхолдеры для цифр из брифинга в квадратных скобках `[15%]`, шаблон
  подсвечивает их.
- `plan`: массив из 4..6 шагов `{title, text, minutes}`, сумма minutes от 45 до 75.
- `source`: массив абзацев исходного КП `{id: "src-N", text}` для раздела
  «Исходное КП» и переходов «Найти в исходном КП». Формирует intake.py, не модель.

Раздел «Методика» модель не заполняет: он статичен и собирается из rubric.yaml
при сборке шаблона.

## 6. rubric.yaml

```yaml
version: "1.0"
author:
  name: Вадим Школьный
  title: коммерческий директор в Серч, ex-коммерческий директор MAX
  channel: ShkolnyiAccount
pillars:            # шесть опор, порядок фиксирован
  - id: 1
    title: Проблема клиента
    question: ...   # на какой вопрос клиента отвечает блок
    fails: [...]    # типичные провалы, попадают в промпт
    post: 35        # id поста-источника
  ...
principles:         # карточки методики, статичный текст и ссылки на посты
  - title: Питч наоборот
    text: ...
    post: 63
personas:           # шаблоны трех читателей
  decider: {label: гендир, matters_hint: ..., reads_hint: ...}
  champion: ...
  executor: ...
voice:              # правила голоса, идут и в промпт, и в проверки typo.py
  banned_patterns: ["—", "·", "не .+, а .+", ...]
  banned_words: [...]
intake_questions:   # шесть вопросов с ключами
  - {key: client, q: Кто клиент}
  ...
```

Из рубрики генерируются: `prompt.md`, блок «Методика» в шаблоне, список запрещенных
паттернов для `typo.py` и для JS-проверки на странице вставки. Тест `test_rubric.py`
проверяет, что сгенерированные файлы в репозитории совпадают с текущей рубрикой
(иначе кто-то правил руками).

## 7. Шаблон и рендер

`template/report.html` содержит стили, разметку-каркас секций и JS. Данных внутри нет:
`<script type="application/json" id="data"></script>` пустой. JS при загрузке:

1. Читает `#data`. Если пусто, показывает состояние «Нет данных» с подсказкой
   вставить JSON (это же поведение использует `docs/index.html`).
2. Валидирует минимально (наличие обязательных ключей), при ошибке печатает список.
3. Рендерит каждую секцию своей функцией: `renderHero(data)`, `renderToc`,
   `renderIntake`, `renderVerdict`, `renderReaders`, `renderBlocks`, `renderFlags`,
   `renderFixed`, `renderPlan`, `renderSource`, `renderFooter`. Методика уже в разметке.
4. Запускает существующие интерактивы (чат, диктофон, экран блокировки, таймер,
   почта, scrollspy) поверх отрендеренной разметки.

JS шаблона разбивается на модули по секциям внутри одного файла, порядок:
утилиты, рендеры, интерактивы, старт. Никаких сборщиков: файл остается одним HTML.

`render.py`:

- `render(data: Report, template: str) -> str`: вставляет JSON (экранируя `</`),
  оборачивает каркасом `<!doctype html><html lang="ru"><head>…` с charset, viewport,
  color-scheme dark, и reset `body{margin:0}img{max-width:100%}[hidden]{display:none!important}`.
- `build_paste()`: собирает `paste.html` из того же шаблона, добавляя панель
  вставки JSON и кнопку «Сохранить HTML», которая формирует standalone-файл
  тем же каркасом и отдает через `<a download>`.

## 8. Промпт и модель

`model.py` вызывает модель через Anthropic API (id модели в конфиге, флаг `--model`) с
системным промптом из rubric и JSON-схемой через structured output. Пользовательское
сообщение: текст КП с якорями `[src-N]` перед абзацами плюс ответы intake.
Невалидный ответ повторяется до двух раз с текстом ошибки валидации. Ключ берется
из `ANTHROPIC_API_KEY`. Перед вызовом печатается оценка токенов.

`prompt.md` для пути без кода: тот же системный промпт, инструкция «вставьте КП и
ответы ниже», и требование ответить только JSON по схеме, схема приложена.

## 9. Типографика и голос (typo.py)

Проход по всем строковым полям отчета:

- nbsp после предлогов и союзов из 1..3 букв, перед частицами же, бы, ли,
  между числом и единицей, в разрядах тысяч.
- ё заменяется на е.
- Кавычки «».

Проверки, которые не правят, а сообщают: «—», «·», конструкции «не X, а Y» и
«это не X, это Y», слова из `voice.banned_words`. CLI печатает список нарушений
с путем до поля. `goodkp check report.json` запускает только проверки.

## 10. Intake

`answers.yaml` с шестью ключами из рубрики. Без файла CLI задает вопросы
интерактивно и сохраняет ответы рядом с КП. Чтение файлов: pdf через `pypdf`,
docx через `python-docx`, pptx через `python-pptx`, txt/md как есть. Абзацы
нумеруются, пустые и короче 20 символов не получают якорь.

## 11. Бот

Одна Vercel-функция на Python, webhook Telegram. На `/start` проверяет
`getChatMember` в обоих каналах (бот должен быть админом в обоих), при подписке
отвечает ссылкой на репозиторий и коротким «как начать», иначе присылает две
ссылки на каналы и кнопку «Проверить снова». Токен, id каналов и ссылка на репо
из переменных окружения. Состояние не хранится.

## 12. Тесты

- `test_schema.py`: golden JSON валиден, невалидные примеры (5 персон, 7 блоков,
  таймер без стопа) отклоняются с понятной ошибкой.
- `test_typo.py`: таблица вход/выход для nbsp и ё, проверки ловят каждый паттерн.
- `test_render.py`: JSON вставлен и экранирован, каркас на месте, `</script>` в
  данных не ломает страницу.
- `test_rubric.py`: сгенерированные файлы совпадают с рубрикой.
- `test_ui.py` (Playwright, chromium): рендер golden JSON, все 11 секций видны,
  в консоли нет ошибок, чат доходит до конца при отключенных анимациях, кнопки
  было/стало переключают текст, скриншот страницы сравнивается с эталоном
  с порогом.
- Живой прогон модели в тесты не входит, есть `scripts/live_run.py` для ручной проверки.

Golden-набор на старте один: СтройМаркет, данные вытаскиваются из прототипа.
Реальные КП от Вадима добавляются в `tests/golden/` по мере поступления.
