# Прогон КП

Скилл живет внутри репозитория good-kp и работает ровно тогда, когда репозиторий под рукой. Вся методика уже написана в `prompt.md`, дублировать ее здесь нельзя: она меняется, и копия разойдется с оригиналом. Скилл отвечает за другое, за порядок действий и за сборку.

Скилл лежит в `REPO/.claude/skills/good-kp/`, то есть `REPO` это папка, внутри которой
лежит `.claude`. Если скилл подключен симлинком из `~/.claude/skills/`, идти надо по
настоящему пути файла, а не по симлинку.

## Что на выходе

Один файл `report.html`, автономный, открывается в любом браузере без сети. Внутри: вердикт голосом клиента, разбор по шести опорам, три читателя, переписанная первая страница КП и план работ на час.

## Порядок

### 1. Прочитать контракт

До первой строчки JSON прочитать целиком:

- `REPO/goodkp/schema.py`: контракт вместе с перекрестными проверками. Он точнее экспортированной JSON-схемы, потому что держит еще и связи между полями.
- `REPO/tests/golden/stroymarket/report.json`: полный образец заполнения на синтетическом КП. Показывает объем, тон и детализацию каждого поля. Без него получится скелет вместо отчета.

### 2. Прочитать методику

`REPO/prompt.md`, разделы «Вводные», «Отказ», «Методика», «Три читателя», «Переписка в шапке отчета», «Правила голоса», «Контракт данных». Раздел «Если ты агент с доступом к репозиторию»: это ты, он короткий и его стоит перечитать даже если кажется, что помнишь.

### 3. Собрать вводные

Нужен текст КП и шесть ответов из раздела «Вводные». Если КП пришло файлом, текст извлечь самому. Если ответов нет, задать шесть вопросов **одним сообщением** и дождаться. По одному вопросу за раз не спрашивать, это выматывает.

Если документ вообще не КП, отчета не будет: заполнить `refusal` с полями `reason` и `hint` и отдать человеку причину словами.

### 4. Написать report.json

Абзацы исходного КП пронумеровать как `src-1..N` и положить в `source`. Считалки, на которых чаще всего валится валидация: шесть опор, три читателя, от восьми до четырнадцати сообщений в переписке, сумма минут в плане от 45 до 75.

### 5. Вычистить запрещенные символы

Самый частый повод для падения. Проверять до валидации, включая текст исходного КП в `source`:

```
grep -n ',\|·\|е\|Е' report.json
```

Тире заменить на запятую или точку, «е» на «е», «·» убрать.

### 6. Собрать

```
uv run --directory REPO python REPO/scripts/build_report.py "$PWD/report.json" "$PWD/report.html"
```

Скрипт валидирует JSON схемой и пишет HTML. Ошибки валидации править **в данных**, не в схеме, и запускать снова, пока не соберется. Если скрипта нет под рукой, подойдет `pip install pydantic` и обычный `python` с `PYTHONPATH=REPO`.

### 7. Отдать

Назвать путь к `report.html` и одной строкой сказать вердикт: сколько опор провалено, сколько шатается, сколько держит. Файл автономный, пересылается как есть.

## Когда репозитория нет

Тот же прогон умеет делать модель в чате без инструментов: она возвращает JSON текстом, человек вставляет его в `goodkp.html` и получает отчет в браузере. Порядок описан в `prompt.md`, раздел «Если ты модель в чате без инструментов». Этот путь нужен продавцу без питона, агенту с репозиторием он не нужен.

## Чего не делать

- Не писать разметку руками. Отчет собирает `template/report.html` из JSON, HTML на выходе никто не правит.
- Не править схему под данные. Схема это контракт, расходится с ней всегда JSON.
- Не копировать сюда методику из `prompt.md`. Она живая, копия устареет за неделю.
- Не смягчать вердикт. Отчет ценен тем, что называет провал провалом, вежливая версия бесполезна.
